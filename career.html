PROJECT 01

KB 자산운용 통합 개편

기간2026.01 ~ 2026.09 (2026.09.21 정식 오픈) 역할PL · Backend Lead · Infra 팀백엔드 3 · 프론트엔드 1 · 퍼블리셔 1

기존 kbam.co.kr과 riseetf.co.kr을 하나로 통합한 자산운용사 홈페이지·어드민 개편. 솔트룩스 협업. 기존 사이트 기준 하루 약 2,000명 접속 규모.

주요 성과

  • 상품·홈페이지 DB 설계 · 마이그레이션 — KB 기존 홈페이지(RISE ETF·KBAM) DB 구조를 파악하고, ETL을 맡은 솔트룩스와 상품 DB 스키마를 협의. 기존 DB 구조를 최대한 따르되 홈페이지에서 추가로 관리하는 정보는 _info 테이블로 분리했고, 기존 데이터와 공지사항·공시·파일·인사이트 콘텐츠 마이그레이션을 직접 진행.
  • 폐쇄망 AWS 인프라 · Docker · Podman 전환 — 완전 폐쇄망 조건에서 매니지드 컨테이너 사용이 어려워 RedHat 기반 Podman으로 이관해 배포 구조를 구성. 이후 폐쇄망 AWS 환경으로 확정되면서 Docker 배포가 가능해져 Docker로 되돌림. 배포 환경이 두 차례 바뀌는 동안에도 Nginx 기반 Blue/Green 무중단 배포와 CI/CD가 그대로 동작하도록 구성.
  • 시계열 데이터 캐싱 최적화 — 상품 가격·구성종목 비율 데이터는 일별로 쌓여 양이 많았고, 리스트·상세 전 구간에서 조회돼 응답이 1~2s까지 지연. 전날 종가 기준으로 자주 조회되는 데이터를 취합해 Redis에 캐시 → 응답 0.2s 수준 (약 80% 개선).
  • 통합 검색 엔진 · ETL 파이프라인 연결 — ETF · Fund · 컨텐츠 · 공지사항까지 한 검색으로 다루기 위해 LIKE 검색의 한계를 넘어, ETL 업체 처리 완료 시점에 스케줄러로 OpenSearch에 데이터 반영 + 캐시 처리까지 파이프라인 구축.
  • 키워드 기반 사이트 설계 · 추천 시스템 (자발 제안) — 사이트 전체를 키워드 중심으로 움직이도록 스스로 제안·설계. 상품·컨텐츠에 키워드를 붙여 상품 진입 시 연관 컨텐츠 자동 추천, 유저가 본 상품 키워드를 정수 체계로 DB에 누적해 유사 상품을 추천하는 구조. 설계·리뷰는 본인이 담당하고 실 구현은 후임 개발자에게 위임.
  • 고객사 요청으로 오픈 직전 재투입 · 전환·오픈 참여 — 오픈 일정이 밀리면서 플러스엑스와 KB 간 계약이 먼저 종료됐고, 이후 KB자산운용 측 요청으로 솔트룩스 소속으로 오픈 준비에 다시 합류. 9월 19일 새벽 DNS IP 전환과 종합 테스트를 거쳐 9월 21일 정식 오픈까지 함께 진행했고, 오픈 이후 홈페이지 유지보수·관제와 배포 자동화를 맡고 있음.

  • 오픈 후 관제 · DB 과부하 해결 (솔트룩스) — 매일 아침 성과 데이터 적재 직후 상품 DB CPU가 98%까지 오르는 문제를 관제 중 확인. 랭킹 캐시를 먼저 지우고 다시 채우는 약 2분 동안 요청이 전부 DB로 몰리던 구조를 전날 값을 유지한 채 덮어쓰도록 바꾸고, 펀드별 전체 이력을 정렬해 최신 수익률을 뽑던 쿼리를 최신 기준일 조회로 교체 → CPU 약 40% 수준.

삼성 디자인 R&D 센터 — 사내 AI 이미지 생성 서비스

기간2025.03 ~ 2025.12 (1·2·3차 전 계약 참여) 역할Backend — JSON 스키마 추상화 · API

삼성 디자인 R&D 센터 디자이너 대상 사내 AI 이미지 생성 서비스. 실사용자 약 300~500명, 해외 디자이너 포함.

주요 성과

  • 컴포넌트 JSON 스키마 추상화 (핵심 담당)
    • 문제 — ComfyUI 기반이라 모델·기능마다 파라미터 조합이 전부 달랐고, 기능 추가 시마다 프론트 UI를 새로 붙이는 방식이 반복돼 확장 속도가 붙지 않음.
    • 해결 — 프롬프트 외 파라미터(사이즈·스텝·프리셋·style strength 등)를 JSON 스키마로 추상화. 프론트에는 공통 컴포넌트(Select · Slider · File · AspectRatio · Presets)만 유지, 백엔드는 기능당 스키마 파일 하나로 UI를 선언하고 프론트가 스키마를 해석해 자동 렌더링.
    • 성과 — 신규 모델·기능 추가가 스키마 정의로 축소. 1·2·3차 계약 동안 SD3.5 → Flux → Kontext → Nunchaku 모델 전환·확장을 UI 리팩터 없이 반복 수행.
  • 편집 기능 API 개발 — Remove · Inpaint · Outpaint · Image Combine · Hand Fixer · Advanced Upscale · Product · CMF · Prompt Edit 등의 백엔드 API 담당.
  • 온프레미스 하드웨어 제약 대응 (자발 제안) — 스토리지가 제한적인 온프레미스 환경에서, 클라이언트 요청 없이 일 단위로 DB·이미지 데이터를 조회해 잔여 이미지를 정리하는 스케줄러를 직접 만들어 반영. I2I 도중 이미지만 첨부하고 이탈하는 케이스, 이미지 삭제 실패로 남는 파일까지 커버.
  • 다국어 대응 (3차) — 해외 디자이너 사용에 맞춰 에러 메시지 다국어 응답과 번역 API 연동 등 백엔드 영역 담당.
  • LLM 기반 프롬프트 보조 — Ollama로 서빙한 gemma3:27b를 백엔드에 연동. 업로드한 참고 이미지의 피사체·배경·색감·조명·분위기를 분석해 생성 프롬프트를 만들고, 시스템 프롬프트에 삼성 제품·카테고리 예시 사전을 넣어 도메인에 맞는 영어 프롬프트 제안, 한국어로 입력하면 자동으로 FLUX Kontext용 영문 프롬프트로 변환.

PROJECT 03

PlusX GenAI — 사내 AI 이미지 생성 플랫폼

기간2025.12 역할Backend · Infra (주도)

사내 자체 AI 이미지 생성 플랫폼. 누적 약 5,000+장 생성.

주요 성과

  • JSON 스키마를 DB로 이전 (앞선 삼성 프로젝트 개선안)
    • 문제 — 앞선 삼성 프로젝트의 JSON 스키마 추상화 방향은 옳았지만, 스키마가 파일에 있어 모델·파라미터 하나 바꾸려면 배포가 필요했고 비개발자가 손댈 수 없었음.
    • 해결 — 스키마 자체를 DB로 이전. 모델 하나당 한 row에 요청 스키마와 UI 스키마를 함께 저장해 워크플로우와 UI가 어긋나지 않도록 구성. UI 컴포넌트는 별도 모델로 카탈로그화해 재사용, 외부 API가 동작하지 않을 때를 대비해 모델별 온/오프 스위치 구성.
    • 성과 — 신규 모델·기능이 어드민에서 row 추가만으로 즉시 반영. Replicate·Fal AI·사내 GPU 서버(ComfyUI)에 모두 대응.
  • 검색을 위한 이미지 키워드 추출
    • 문제 — 프롬프트 텍스트 기반 검색만으로는 한계. 디자인 회사 특성상 이미지의 '느낌'이나 분위기로 검색하려는 경우가 많은데 프롬프트 문구에는 잘 드러나지 않고, 유저가 이미지마다 키워드를 직접 입력할 수도 없음.
    • 해결 — 삼성 프로젝트에서 만든 이미지 분석 기능을 검색용으로 확장. 이미지 생성이 끝나면 비동기로 gemma3:27b가 생성 이미지와 원래 프롬프트를 함께 보고 키워드 최대 15개를 0~1 가중치와 함께 JSON으로 반환. 가중치 0.3 초과 키워드만 저장해 검색 대상으로 활용하고, 결과 편중은 가중치 랭킹(키워드 매칭 70% / 조회수 20% / 북마크 10%)으로 정확도와 다양성 확보.
    • 성과 — 유저가 따로 입력하지 않아도 이미지 생성 시점에 검색용 키워드가 자동으로 쌓이는 구조.
  • 프롬프트 확장 · 번역 — 짧은 프롬프트를 이미지 생성용 상세 영어 프롬프트로 확장하는 Prompt Enhancer 개발, 한국어 입력은 영어로 번역해 처리. 텍스트 처리는 gemma3:27b, 이미지 분석은 qwen3-vl:8b를 Ollama로 연동.
  • LLM 기능 사내 GPU 이전 — 키워드 추출처럼 빠르게 응답하는 LLM 기능을 사내 GPU 서버로 옮겨 비용 절감.
