KB 자산운용 통합 개편

기간2026.01 ~ 2026.07 (Launch 2026.08.10) 역할PL · Backend Lead · Infra 팀백엔드 3 · 프론트엔드 1 · 퍼블리셔 1

기존 kbam.co.kr과 riseetf.co.kr을 하나로 통합한 자산운용사 홈페이지·어드민 개편. 솔트룩스 협업. 기존 사이트 기준 하루 약 2,000명 접속 규모.

주요 성과

  • 다중 데이터 소스 통합 · 방향 전환 대응 — 제로인·FnGuide·KB 내부 DB 등 서로 다른 데이터 소스의 스키마 분석·통합 설계로 시작. 프로젝트 중반 클라이언트가 KB 내부 DB 단일 소스로 방향을 바꾸면서, 해당 DB 스키마 기준으로 다시 정리해 대응.
  • 폐쇄망 AWS 인프라 · 컨테이너 런타임 재선정 — 완전 폐쇄망 조건에서 매니지드 컨테이너 사용이 어려워 RedHat 기반 Podman으로 이관해 배포 구조를 구성. 이후 환경이 폐쇄망 AWS로 정리되며 Docker 배포가 가능해져 Docker로 되돌림. 런타임이 두 차례 바뀌는 동안에도 Nginx 기반 Blue/Green 무중단 배포와 GitHub Actions CI/CD는 유지되도록 구성.
  • 시계열 데이터 캐싱 최적화 — 수익률·구성종목 비율·가격 등 시계열 데이터가 리스트·상세 전 구간에서 반복 조회돼 응답이 1~2s까지 지연. 전날 종가 기준으로 자주 조회되는 데이터를 취합해 Redis에 캐시 → 응답 0.2s 수준 (약 80% 개선).
  • 통합 검색 엔진 · ETL 파이프라인 연결 — ETF · Fund · 컨텐츠 · 공지사항까지 한 검색으로 다루기 위해 LIKE 검색의 한계를 넘어, ETL 업체 처리 완료 시점에 스케줄러로 OpenSearch에 데이터 반영 + 캐시 처리까지 파이프라인 구축.
  • 키워드 기반 사이트 설계 · 추천 시스템 (자발 제안) — 사이트 전체를 키워드 중심으로 움직이도록 스스로 제안·설계. 상품·컨텐츠에 키워드를 붙여 상품 진입 시 연관 컨텐츠 자동 추천, 유저가 본 상품 키워드를 정수 체계로 DB에 누적해 유사 상품을 추천하는 구조. 설계·리뷰는 본인이 담당하고 실 구현은 후임 개발자에게 위임.

기간2025.03 ~ 2025.12 (1·2·3차 전 계약 참여) 역할Backend — JSON 스키마 추상화 · API

삼성 디자인 R&D 센터 디자이너 대상 사내 AI 이미지 생성 서비스. 실사용자 약 300~500명, 해외 디자이너 포함.

주요 성과

  • 컴포넌트 JSON 스키마 추상화 (핵심 담당)
    • 문제 — ComfyUI 기반이라 모델·기능마다 파라미터 조합이 전부 달랐고, 기능 추가 시마다 프론트 UI를 새로 붙이는 방식이 반복돼 확장 속도가 붙지 않음.
    • 해결 — 프롬프트 외 파라미터(사이즈·스텝·프리셋·style strength 등)를 JSON 스키마로 추상화. 프론트에는 공통 컴포넌트(Select · Slider · File · AspectRatio · Presets)만 유지, 백엔드는 기능당 스키마 파일 하나로 UI를 선언하고 프론트가 스키마를 해석해 자동 렌더링.
    • 성과 — 신규 모델·기능 추가가 스키마 정의로 축소. 1·2·3차 계약 동안 SD3.5 → Flux → Kontext → Nunchaku 모델 전환·확장을 UI 리팩터 없이 반복 수행.
  • 편집 기능 API 개발 — Remove · Inpaint · Outpaint · Image Combine · Hand Fixer · Advanced Upscale · Product · CMF · Prompt Edit 등의 백엔드 API 담당.

  • 다국어 대응 (3차) — 해외 디자이너 사용에 맞춰 에러 메시지 다국어 응답과 번역 API 연동 등 백엔드 영역 담당.

PROJECT 03

PlusX GenAI — 사내 AI 이미지 생성 플랫폼

기간2024.04 ~ 2026.08 역할Backend · Infra (단독)

사내 자체 AI 이미지 생성 플랫폼. 누적 약 5,000+장 생성.

주요 성과

  • JSON 스키마를 DB로 이전 (앞선 삼성 프로젝트 개선안)
    • 문제 — 앞선 삼성 프로젝트의 JSON 스키마 추상화 방향은 옳았지만, 스키마가 파일에 있어 모델·파라미터 하나 바꾸려면 배포가 필요했고 비개발자가 손댈 수 없었음.
    • 해결 — 스키마 자체를 DB로 이전. 모델 하나당 한 row에 요청 스키마와 UI 스키마를 함께 저장해 워크플로우와 UI가 어긋나지 않도록 구성. UI 컴포넌트는 별도 모델로 카탈로그화해 재사용, 모델별 활성/비활성은 데이터 스위치로 제어.
    • 성과 — 신규 모델·기능이 어드민에서 row 추가만으로 즉시 반영. Sagemaker → Flux.1 dev → Fal AI 모델 교체를 배포 없이 진행.
  • 이미지 검색 · 프롬프트 밖의 검색성
    • 문제 — 프롬프트 텍스트 기반 검색만으로는 한계. 디자인 회사 특성상 이미지의 '느낌'이나 분위기로 검색하려는 경우가 많은데 프롬프트 문구에는 잘 드러나지 않음.
    • 해결 — 이미지 생성 완료 시점에 사내 GPU 서버로 image-to-keyword를 돌려 이미지 자체에서 키워드를 추출해 검색 대상으로 활용. 결과 편중은 가중치 랭킹(키워드 매칭 70% / 조회수 20% / 북마크 10%)으로 정확도와 다양성 확보.
  • 사내 GPU 서버 구축·보안 강화 — Sagemaker → 사내 GPU 이전, Iptables 기반 보안(외부 IP SSH 차단, API 호출 제어), 인증 토큰·프록시 서버 구축.
  • Figma Plugin 자체 제작 (자발 제안) — 디자인 회사 특성상 피그마 사용이 잦은 점에 착안, 피그마 안에서 GenAI를 호출해 이미지를 바로 삽입하는 플러그인을 자체 제작. 배포 전 단계까지 직접 테스트 완료.
  • Company 계층형 도메인 — Guest 회사 데이터 격리, 회사별 크레딧·기간 관리, 이메일 로그인, 원가·사용량 대시보드.
